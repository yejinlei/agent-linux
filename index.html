一、总纲：内核即本体 · 万法皆结构

Linux内核本体论不是抽象的哲学比喻，而是以源码为本体、以数据结构为骨架、以函数指针表为多态、以调用链为因果的精确工程映射。

诸法无我 → 一切皆文件

VFS用file_operations函数指针表统一普通文件、socket、设备、管道的接口。没有哪个对象是"特殊"的，一切皆通过vnode假名安立，read/write是通用法。

源码路径：include/linux/fs.h

一即一切 → 宏内核单地址空间

所有子系统共享同一内核地址空间，没有微内核的IPC开销。通过struct内嵌和container_of宏实现面向对象继承，互摄互入、零拷贝交互。

设计哲学：Linus Torvalds, 1991

缘起性空 → 引用计数RCU

所有内核对象都通过kref/refcount管理生命周期，缘起则聚（kobject_get）、缘尽则散（kobject_put→release）。RCU读复制更新实现无锁并发，性空而妙用无穷。

源码路径：include/linux/kref.h, include/linux/rcupdate.h

三、进程调度本体 · 分类+状态驱动

L1 结构本体：struct task_struct

进程的身份证，包含超过300个字段，定义在 include/linux/sched.h，所有进程管理算法围绕它构建。

// include/linux/sched.h 核心字段（6.12内核）
struct task_struct {
    volatile long state;          // 进程状态：TASK_RUNNING/INTERRUPTIBLE/UNINTERRUPTIBLE等
    void *stack;                // 进程内核栈指针
    atomic_t usage;             // 引用计数
    int prio, static_prio, normal_prio; // 动态/静态/正常优先级
    unsigned int rt_priority; // 实时优先级 0-99
    const struct sched_class *sched_class; // 所属调度类（插件入口）
    struct sched_entity se;   // 调度实体（CFS用）
    struct sched_rt_entity rt; // 实时调度实体
    struct sched_dl_entity dl; // deadline调度实体
    struct mm_struct *mm;    // 进程虚拟地址空间（内核线程为NULL）
    struct files_struct *files; // 打开的文件描述符表
    struct fs_struct *fs;      // 文件系统相关信息（cwd/root）
    pid_t pid;                  // 进程ID
    struct task_struct *parent; // 父进程
    struct list_head children; // 子进程链表
    struct files_struct *files; // 打开文件表
    struct signal_struct *signal; // 信号处理
    // ... 共300+字段
};

L2 行为本体：调度类五级优先级链表

调度器采用插件式架构，pick_next_task按优先级从高到低遍历调度类，第一个返回非NULL的任务被选中执行：

// kernel/sched/core.c 优先级从高到低
extern const struct sched_class stop_sched_class;   // 停机任务，最高优先级，抢占一切
extern const struct sched_class dl_sched_class;     // Deadline 限期任务，保证截止时间
extern const struct sched_class rt_sched_class;     // 实时任务 FIFO/RR，优先级0-99
extern const struct sched_class fair_sched_class;   // 普通进程 CFS/EEVDF，nice值-20~19
extern const struct sched_class idle_sched_class;   // 空闲任务，CPU无事可做时运行

// sched_class 函数指针表（多态接口）
struct sched_class {
    struct task_struct * (*pick_next_task)(struct rq *rq);
    void (*enqueue_task)(struct rq *rq, struct task_struct *p, int flags);
    void (*dequeue_task)(struct rq *rq, struct task_struct *p, int flags);
    void (*task_tick)(struct rq *rq, struct task_struct *p, int queued);
};

L2 行为本体：进程状态机

L3 语义本体：从CFS到EEVDF的公平演进

CFS（Completely Fair Scheduler，2.6.23引入）：用红黑树管理调度实体，vruntime记录进程已运行的虚拟时间，总是选vruntime最小的进程运行。nice值对应权重，nice 0权重1024，每差1级权重差约10%。

EEVDF（Earliest Eligible Virtual Deadline First，6.6内核正式取代CFS）：解决CFS在IO密集型与CPU密集型混部时的响应延迟问题，引入lag（虚拟时间亏欠）和virtual deadline概念，优先选"eligable且deadline最早"的实体，交互延迟降低约30%。

// EEVDF 核心判定逻辑（kernel/sched/fair.c）
// 1. 计算实体的lag = 应得运行时间 - 实际运行时间
// 2. lag > 0 的实体为 eligible（有亏欠，有资格运行）
// 3. 在 eligible 实体中选 virtual deadline 最早的
// virtual_deadline = vruntime + slice / weight（权越小，deadline越短）

四、内存管理本体 · 映射+分类驱动

L1 结构本体：三大基石结构体

struct page

物理页框的身份证，系统中每个4KB页对应一个page实例，全局数组mem_map存储。极度节省空间，大量使用union和位域。

路径：include/linux/mm_types.h

struct mm_struct

进程虚拟地址空间总描述符，每个进程一个。包含pgd（页全局目录根）、mmap（VMA链表头）、mm_rb（VMA红黑树根）、代码/堆/栈边界。

路径：include/linux/mm_types.h

struct vm_area_struct

一段连续虚拟地址区间（VMA），相同权限/属性。用链表+红黑树双组织：链表便于遍历，红黑树便于O(log n)查找地址所属VMA。缺页异常核心查找对象。

路径：include/linux/mm_types.h

L2 行为本体：四级页表地址翻译（x86_64）

64位虚拟地址拆分为9+9+9+9+12位，逐级查找：PGD→PUD→PMD→PTE→物理页+页内偏移。TLB缓存最近翻译结果，未命中才走页表遍历。

L2 行为本体：三级内存分配器

伙伴系统（Buddy System）

管理连续物理页框，分配阶数0~10（4KB~4MB）。核心算法：找最小满足阶的块，不够则分裂大块为两个伙伴；释放时检查伙伴是否空闲，是则合并。解决外碎片问题。

源码：mm/page_alloc.c

Slab/Slub/Slob分配器

基于伙伴系统提供小内存（小于一页）分配，为常用对象（task_struct/inode/sk_buff等）建立专用缓存池，复用已释放对象，避免初始化开销。默认用Slub（更高效）。

源码：mm/slub.c

vmalloc

分配虚拟地址连续但物理地址不连续的内存，用于不需要物理连续的大内存分配。通过修改页表建立映射，有一定开销，不用于DMA。

源码：mm/vmalloc.c

L3 语义本体：写时复制（Copy-On-Write）——缘起性空的极致体现

fork()创建子进程时并不复制全部内存页，而是让父子进程共享所有页表项，页标记为只读。当任何一方尝试写入时，触发缺页异常，内核此时才复制该物理页，各自拥有独立副本。

哲学对应：未写时共享是"性空"，写入时复制是"缘起"，惰性计算、按需分配，最小化不必要的劳动——这与佛教"应无所住而生其心"异曲同工。

五、中断机制本体 · 过程驱动

三级中断流水线：上半部快速响应，下半部延迟处理

中断的核心矛盾：必须足够快响应硬件（否则丢数据），但处理逻辑可能很复杂（否则占用CPU太久）。Linux的解决方案是分层：

L1 结构本体：struct irq_desc 中断描述符

// include/linux/irqdesc.h 每个中断号对应一个
struct irq_desc {
    struct irq_data irq_data;        // 中断芯片、硬件中断号、状态
    struct irqaction *action;    // 中断处理函数链表（共享中断）
    const char *name;          // 中断名称，/proc/interrupts可见
    unsigned int number;       // Linux虚拟中断号
    struct irq_chip *chip;     // 中断控制器操作（mask/unmask/ack）
};

L3 语义本体：NAPI——中断+轮询的中道智慧

纯中断：高流量下中断风暴，CPU全在处理中断，活都干不完；纯轮询：低流量下浪费CPU空转。NAPI采用混合模式：第一个包到来触发硬中断，之后关闭中断进入轮询模式处理一批包，处理完再开中断。高流量时近似轮询效率，低流量时近似中断低延迟，是"行于中道"的典型设计。

六、TCP/IP协议栈本体 · 状态+过程驱动（重点子模块）

TCP/IP协议栈是内核中最复杂的子系统，本身构成一个自洽的本体论体系：以sk_buff为血脉，以四层封装为流转，以TCP状态机为因果，以Netfilter为关口。

L1 结构本体：sk_buff——网络包的血脉

sk_buff（socket buffer）是贯穿整个网络栈的核心数据结构，从网卡驱动接收一直到用户态read，所有协议层操作都通过移动指针实现零拷贝逐层加头/去头：

// include/linux/skbuff.h 核心字段
struct sk_buff {
    struct sk_buff *next, *prev;  // 双向链表，挂在发送/接收队列
    struct sock *sk;             // 所属socket
    struct net_device *dev;    // 收发网卡
    
    // 四大核心指针：零拷贝分层关键
    unsigned char *head, *data, *tail, *end;
    
    // 各层首部指针，由各层设置
    struct ethhdr *mac_header;
    struct iphdr *network_header;
    struct tcphdr *transport_header;
    
    __u32 len;               // 数据总长度
    __be16 protocol;         // 上层协议类型（ETH_P_IP等）
    ktime_t tstamp;         // 收包时间戳
};

L2 行为本体：顺逆缘起——发送封装与接收解封装

发送路径（顺缘起）：应用层write() → 传输层加TCP头 → 网络层加IP头 → 链路层加Ethernet头 → 网卡驱动发送。每一层只移动data指针向前push，不拷贝数据。

接收路径（逆缘起）：网卡硬中断收包 → 链路层校验去掉Ethernet头 → 网络层路由去掉IP头 → 传输层处理TCP/UDP → 放入socket接收队列 → 应用层read()。每一层pull掉本层头部。

L2 行为本体：TCP状态机——11个状态的因果流转

三次握手：CLOSED → SYN_SENT → ESTABLISHED（主动打开）；CLOSED → LISTEN → SYN_RECV → ESTABLISHED（被动打开）。三事和合（client SYN、server SYN+ACK、client ACK），连接方成。

四次挥手：ESTABLISHED → FIN_WAIT1 → FIN_WAIT2 → TIME_WAIT → CLOSED（主动关闭）；ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED（被动关闭）。TIME_WAIT等待2MSL确保最后一个ACK被对方收到，是对因果负责。

运维三大坑：SYN_RECV洪泛攻击、CLOSE_WAIT泄漏（应用没调close）、TIME_WAIT过多（短连接）。

匹配驱动本体：Netfilter五钩子——因果关口

Netfilter在网络栈五个关键点设置钩子，iptables/nftables规则挂在钩子上，实现防火墙、NAT、连接跟踪功能，是典型的匹配-回调架构：

// include/linux/netfilter.h 五个钩子点
enum nf_inet_hooks {
    NF_INET_PRE_ROUTING,  // 刚进入网络层，还没路由，DNAT在这里
    NF_INET_LOCAL_IN,     // 路由后确定是发往本机，INPUT防火墙
    NF_INET_FORWARD,      // 路由后需要转发，FORWARD防火墙
    NF_INET_LOCAL_OUT,    // 本机进程发出的包，OUTPUT防火墙
    NF_INET_POST_ROUTING, // 即将发出网卡，SNAT在这里
};

// conntrack连接跟踪：阿赖耶识，记录所有连接状态，NAT依赖它

分类驱动本体：拥塞控制——可插拔算法框架

拥塞控制通过tcp_congestion_ops函数指针表实现插件化，内核支持多个算法动态切换：

CUBIC（默认）

基于三次函数的窗口增长曲线，窗口增长与RTT无关，对不同RTT流公平，适用于长肥管道。丢包后乘法减小，然后按三次函数快速恢复到公平窗口。

BBR（Google，4.9引入）

基于带宽和延迟乘积模型，不把丢包作为拥塞信号，而是主动探测最大带宽和最小RTT，在长肥管道和跨洋链路上吞吐量比CUBIC高2-10倍，不制造buffer bloat。

七、文件系统本体 · 映射+分类驱动

VFS四大对象：一切皆文件的抽象基石

VFS通过四大对象抽象，统一了ext4/XFS/Btrfs等磁盘文件系统、proc/sysfs等伪文件系统、tmpfs内存文件系统、FUSE用户态文件系统、socket/pipe等特殊文件，所有文件都通过统一的file_operations接口访问，实现了"一切皆文件"的哲学。

八、驱动与虚拟化本体 · 匹配+边界驱动

设备模型：bus-device-driver三位一体

Linux设备模型是面向对象设计在C语言中的典范：kobject提供引用计数和sysfs基础，bus_type是总线，device是设备，driver是驱动。总线负责匹配，匹配成功调用driver的probe()函数完成初始化。

九、系统调用门 · 边界驱动

系统调用是用户态（Ring3）进入内核态（Ring0）的唯一官方入口。x86_64下通过syscall指令触发，参数放在rdi/rsi/rdx/r10/r8/r9寄存器，系统调用号放在rax，执行后切换到内核栈，查系统调用表分发到对应处理函数。
