本体化知识体系

总纲 · 内核即本体

诸法无我 · 一切皆文件

内核所有实体都通过VFS抽象为文件接口：普通文件、目录、设备、管道、socket、甚至进程信息都以文件形式呈现，统一用open/read/write/close操作。

本体根基：所有资源假名安立，无自性，依统一接口显现差别相。

一即一切 · 宏内核圆融

所有核心子系统运行在同一内核地址空间，函数直接调用无需消息传递，调度、内存、网络、文件系统互摄互入，一个子系统的优化整体受益。

本体根基：单地址空间法界，全体即一，一即全体。

缘起性空 · 引用计数

所有内核对象生命周期都由引用计数（kref/refcount）管理：缘聚则生（引用计数>0），缘散则灭（引用计数归0自动释放），无常驻不变的实体。

本体根基：一切对象因缘和合而生，因缘散尽而灭，性空缘起。

三大设计原则（本体元公理）

1

机制与策略分离

内核只提供通用机制（如何做），不硬编码具体策略（做什么）。例如调度器只提供调度类框架，CFS/RT/DL等具体调度策略以模块形式挂载，用户可自定义。

2

为常见情况优化

优先优化99%的常见场景，边缘场景可接受较慢。例如VFS路径查找优先命中dentry缓存，缺页异常优先处理匿名页，都是面向高频路径优化。

3

可扩展优于极致性能

通过函数指针表、回调钩子、挂载点等设计保证可扩展性，新硬件、新协议、新文件系统可通过模块接入无需修改核心代码，追求长期演化能力而非单点性能。

内核核心本体架构

核心实体：task_struct（进程描述符）

include/linux/sched.h · Linux 6.12
// 内核中每个进程/线程的唯一身份证 struct task_struct { volatile long state; // 进程状态：运行/就绪/睡眠/僵尸 void *stack; // 内核栈指针 pid_t pid; // 进程ID struct mm_struct *mm; // 内存描述符（内核线程为NULL） struct files_struct*files; // 打开的文件描述符表 struct sched_entityse; // 调度实体（CFS调度用） struct task_struct *parent; // 父进程指针 char comm[TASK_COMM_LEN]; // 进程名（最长15字节） int prio, static_prio; // 动态/静态优先级 };
task_struct就像是每个进程的「身份证+人事档案」：state是当前状态（上班/摸鱼/睡觉/离职），pid是工号，mm是你专属的办公空间（内存），files是你有权限打开的文件列表，se是绩效考核记录（调度器用它给你分配CPU时间）。

调度器本体：EEVDF（最早虚拟截止时间优先）

kernel/sched/fair.c · 2023年6.6版本正式替代CFS

调度框架是典型的分类驱动本体：通过struct sched_class函数指针表实现多态，五个调度类优先级从高到低：

  1. stop_sched_class：最高优先级，停机调度类，内核关键任务用
  2. dl_sched_class：Deadline调度类，硬实时任务用
  3. rt_sched_class：实时调度类，软实时任务用
  4. fair_sched_class：EEVDF/CFS完全公平调度类，99%普通进程用
  5. idle_sched_class：空闲调度类，CPU没事干时跑idle线程

EEVDF核心思想：给每个进程计算「虚拟截止时间」，总是选最早截止的进程运行，比CFS红黑树选最左节点更公平，响应延迟更低。

调度类就像公司的职级体系：董事长（stop）→ 高管（dl）→ 中层（rt）→ 普通员工（fair）→ 保洁（idle），高优先级的人要办事时，低优先级的必须立刻让出CPU。EEVDF就是普通员工的绩效考核系统，保证每个人分到的CPU时间公平，不摸鱼也不被压榨。

进程状态机

核心实体：mm_struct（内存描述符）

include/linux/mm_types.h · Linux 6.12
// 每个进程独有的地址空间描述符 struct mm_struct { struct vm_area_struct *mmap; // VMA链表头（虚拟内存区域） struct rb_root mm_rb; // VMA红黑树根（快速查找用） pgd_t *pgd; // 页全局目录（四级页表起点） unsigned long start_code, end_code; // 代码段起止 unsigned long start_brk, brk; // 堆的起止（malloc用brk扩展） unsigned long start_stack; // 用户栈起始地址 atomic_t mm_count; // 引用计数（线程共享时计数） };
mm_struct就是每个进程的「私人内存地图」：mmap和mm_rb是地图的两种索引方式（链表适合遍历，红黑树适合快速查找），pgd是地图的总目录（四级页表的起点），堆、栈、代码段、数据段都在地图上划好了区域。进程之间的地图完全独立，互相看不到对方的地址，这就是虚拟内存的隔离性。

三级内存分配器体系

mm/ 目录下伙伴系统+Slab+vmalloc

1. 伙伴系统（Buddy System）

以页（通常4KB）为单位分配大块连续物理内存，解决外部碎片问题：两个大小相同且地址连续的块互为「伙伴」，释放时如果伙伴空闲就合并成更大的块。

2. Slab/Slub分配器

在伙伴系统之上，专门分配小内核对象（比如task_struct、sk_buff、inode都是常用小对象），每种对象有专属缓存，预分配一批对象重复使用，避免反复分配释放页，解决内部碎片。

3. vmalloc分配器

分配虚拟地址连续但物理地址不连续的大内存块，用于不要求物理连续的场景（比如内核模块加载、大缓冲区），通过页表把不连续的物理页映射到连续的虚拟地址。

内存分配器就像物流公司的仓储系统：伙伴系统是整集装箱（页）批发，保证连续的大片空间；Slab是常用小件（小对象）的货架，预先摆好常用规格，拿取极快；vmalloc是拼箱，不要求货物物理上挨在一起，只要在送货单（页表）上看起来是连续的就行。

三级中断处理流水线

kernel/irq/ + include/linux/interrupt.h

中断是典型的过程驱动本体，为解决中断处理耗时太长导致系统卡顿的问题，内核把中断处理拆成三级，越往后优先级越低、可延迟执行：

① 硬中断顶半部（HardIRQ）

特点：不可屏蔽、不可抢占、执行时关中断，必须极快

做什么：只做最紧急的事——确认硬件中断、把硬件数据拷贝到内存、登记中断事件，然后立刻触发软中断

类比：你正在工作时电话响了，你立刻接起说"我稍后回你"然后挂掉，不耽误手上的事

② 软中断（SoftIRQ）

特点：可抢占、开中断执行，最多有32个软中断类型，每个CPU独立执行

做什么：处理大部分耗时工作，比如网络包收/发、块设备IO完成、定时器处理

类比：挂掉电话后，你把手头紧急的事做完，然后回电话处理事情

③ 工作队列（Workqueue）

特点：运行在内核线程上下文，可以睡眠、可以被调度、甚至可以获取信号量

做什么：处理非常耗时的工作，比如磁盘文件系统操作、需要等待IO的任务

类比：如果事情太复杂电话里说不清楚，你把它记在待办清单上，专门安排时间慢慢处理

NAPI：中断+轮询混合机制

net/core/dev.c · 网络高性能核心机制

纯中断模式在网络流量大时会产生中断风暴（每个包都触发一次中断，CPU全耗在处理中断上），NAPI（New API）解决了这个问题：

  1. 第一个包到来时触发硬中断，驱动关闭该网卡的中断，把网卡加入轮询列表
  2. 软中断中轮询网卡，批量处理所有积压的包（一次处理最多budget=64个包）
  3. 包处理完后重新打开网卡中断，等待下一次中断触发
NAPI就像外卖送餐：刚开始你听到门铃响一次（第一个中断），你就把门打开，告诉外卖员"后面的外卖直接放门口就行，不用按门铃了"，然后你批量把所有外卖拿进来，拿完再关上门等下一次门铃。流量小的时候和普通中断一样灵敏，流量大的时候不会被门铃烦死。

同步原语决策树

内核同步原语分类

自旋锁（spinlock_t）

拿不到锁时原地循环等待，不睡眠、不调度，开销小，适合临界区极短、且不能睡眠的场景（比如硬中断上下文）。单CPU上自旋锁直接关抢占。

互斥锁（mutex）

拿不到锁时进程睡眠，让出CPU，适合临界区较长、允许睡眠的场景（进程上下文），开销比自旋锁大但不浪费CPU。

读写信号量（rw_semaphore）

读者共享、写者独占，适合读多写少的场景（比如VFS的inode查找），可以睡眠。

RCU（读-拷贝-更新）

读侧完全无锁、无等待，极高性能，写侧拷贝旧数据修改后替换指针，等待所有读侧退出旧数据生命周期后再释放。适合读极多写极少的场景（比如路由表、文件系统dentry缓存），是内核高性能并发的核心秘密。

同步原语适用场景矩阵

场景 自旋锁 互斥锁 RCU
中断上下文 ✅ 可用 ❌ 不可 ✅ 可用
可睡眠 ❌ 不可 ✅ 可以 ❌ 读侧不可
临界区短 ✅ 优 可 ✅ 优
临界区长 ❌ 差 ✅ 优 可
读多写少 可 可 ✅ 最优
同步原语就像公共场所的锁：自旋锁是公共卫生间的门，你站在门口等，不能走开，适合很快就出来的场景；互斥锁是餐厅排队叫号，你可以坐着等，不用站在门口，适合要等很久的场景；RCU是换指示牌，读的人不用停，直接看当前指示牌就行，写的人偷偷把新牌子做好，等所有人都看完旧牌子再把旧牌子换掉，读完全无等待，性能最高。

TCP/IP 协议栈本体

核心实体：sk_buff（网络包缓冲区）

include/linux/skbuff.h · 网络协议栈最核心的数据结构
// 网络包从网卡到应用、从应用到网卡全程唯一载体 struct sk_buff { struct sk_buff *next, *prev; // 链表指针，组成包队列 unsigned char *head, *data; unsigned char *tail, *end; // 四个核心指针管理包数据 __be16 protocol; // 上层协议类型（IP/ARP等） struct net_device*dev; // 经过的网卡设备 struct sock *sk; // 所属的socket ktime_t tstamp; // 收包时间戳 };

四个指针的精妙设计：head和end标记整个缓冲区的起止（固定），data和tail标记实际有效数据的起止（可移动）。

  • • 发送时向下层传递，调用skb_push()把data往前移，加下层协议头
  • • 接收时向上层传递，调用skb_pull()把data往后移，剥掉下层协议头

四层封装/解封装指针移动示意

sk_buff就像快递包裹：head和end是快递盒的外边界，data是你当前拆到的位置，tail是包裹里东西的结束位置。发快递的时候你先放东西（应用数据），然后套一层气泡袋（TCP头），再套一层纸盒（IP头），再套一层快递袋（MAC头），每次套袋子data就往前移；收快递的时候你从外到里一层一层拆袋子，data就往后移，直到拿到里面的东西。全程不需要拷贝数据，只移动指针，这是网络栈高性能的核心秘密！

TCP 状态机

include/net/tcp.h · TCP_ESTABLISHED等11个状态

三次握手/四次挥手时序

三次握手（建立连接）

  1. ① 客户端发SYN → 进入SYN_SENT状态
  2. ② 服务端收SYN，回SYN+ACK → 进入SYN_RECV状态
  3. ③ 客户端收SYN+ACK，发ACK → 双方进入ESTABLISHED状态，连接建立

为什么是三次？因为要双向确认序列号，两次的话服务端不知道客户端有没有收到自己的SYN。

四次挥手（断开连接）

  1. ① 主动关方发FIN → 进入FIN_WAIT1
  2. ② 被动关方回ACK → 进入CLOSE_WAIT，主动关方进入FIN_WAIT2
  3. ③ 被动关方发FIN → 进入LAST_ACK
  4. ④ 主动关方回ACK → 进入TIME_WAIT，等待2MSL后关闭

为什么TIME_WAIT要等2MSL？防止最后一个ACK丢失导致被动关方重发FIN没人收，保证所有旧连接的包都在网络中消失。

TCP连接就像打电话：三次握手是"喂能听到吗？""能听到，你能听到我吗？""能听到，我们说话吧"，双方确认信道通畅；四次挥手是"我说完了，我要挂了""好的我知道了""我也说完了，挂吧""好的拜拜"，双方确认都把话说完了，不会突然挂电话导致对方话没说完。

文件系统本体

VFS四大核心对象

include/linux/fs.h · 一切皆文件的抽象基础

super_block

超级块，代表一个已挂载的文件系统实例，存储文件系统整体信息（块大小、最大文件数、魔数、挂载点），每个挂载的文件系统一个。

inode

索引节点，代表一个实际存在的文件/目录/设备，存储元数据（大小、权限、所有者、块位置、修改时间），一个文件对应唯一inode，和文件名无关。

dentry

目录项，代表路径中的一个分量（比如/usr/bin/ls里的usr、bin、ls都是dentry），缓存路径到inode的映射，加速路径查找，存在内存中不持久化到磁盘。

file

文件对象，代表进程打开的一个文件实例，存储打开模式、当前读写偏移、f_op操作表，每个open()就产生一个新file结构体，多个进程打开同一个文件会有多个file但共享inode。

VFS四大对象就像公司档案系统：super_block是整个档案库，记录总共有多少档案、用什么分类法；inode是档案本身，记录文件内容位置和属性，和你怎么找它无关；dentry是目录卡片柜，记录"哪个名字对应哪个档案"，放在前台方便快速查找；file是你手里的档案借阅卡，记录你打开了哪个档案、读到第几页了，每个人打开同一份档案都有自己的借阅卡，互不影响。

include/linux/fs.h · 一切皆文件的核心机制
struct file_operations { ssize_t (*read) (struct file *, char __user *, size_t, loff_t *); ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *); int (*open) (struct inode *, struct file *); int (*release)(struct inode *, struct file *); long (*unlocked_ioctl)(struct file *, unsigned int, unsigned long); int (*mmap) (struct file *, struct vm_area_struct *); };

这就是"一切皆文件"的终极秘密：不管是普通文件、字符设备（比如终端/dev/tty）、块设备（磁盘）、socket、甚至进程信息/proc下的文件，只要实现了这套file_operations函数指针表，就能用统一的read/write/open/close系统调用操作。VFS根本不关心底层是什么，只要调对应函数指针就行，完美的面向对象多态，纯C语言通过函数指针实现，比C++虚表更轻量。

驱动与虚拟化本体

设备模型：bus-device-driver 三位一体

include/linux/device.h · 2.6版本引入的统一设备模型

设备模型是典型的匹配驱动本体：所有设备和驱动都挂在总线上，总线负责把匹配的设备和驱动绑定到一起，自动调用probe()函数初始化。

bus（总线）

管理挂在该总线上的所有设备和驱动，提供match()回调判断设备和驱动是否匹配（比如PCI总线看vendor/device ID，USB看VID/PID，平台总线看compatible字符串）。典型总线：PCI、USB、platform、I2C、SPI。

device（设备）

代表一个实际存在的硬件设备，挂在总线上，包含硬件资源信息（IO端口、中断号、MMIO地址、DMA掩码），可以通过设备树（Device Tree）或ACPI枚举出来。

driver（驱动）

代表一个设备驱动，挂在总线上，包含支持的设备ID列表、probe()/remove()回调，当总线匹配到设备和驱动时，调用probe()初始化硬件、注册字符/块设备、分配中断处理函数。

设备模型就像婚介所：总线是婚介所，手里有所有单身男（设备）和单身女（驱动）的资料，match()函数就是匹配条件（年龄/身高/收入/硬件ID），条件符合就安排见面（调用probe()），配对成功就绑定在一起，设备就可以正常工作了。新硬件加进来就登记为新的单身男，新驱动加进来就登记为新的单身女，自动匹配不需要修改内核核心代码。

容器：Namespace 隔离六大边界

include/linux/nsproxy.h · Docker/LXC底层内核机制

容器本质就是一个普通进程，只是通过Namespace开启了资源隔离，让它"看起来"拥有自己独立的整个系统，六大Namespace分别隔离：

  • Mount Namespace：隔离挂载点，容器内看不到宿主机的文件系统，有自己独立的挂载树
  • PID Namespace：隔离进程ID，容器内PID=1是init进程，看不到宿主机的其他进程
  • Network Namespace：隔离网络栈，容器有自己独立的网卡、路由表、iptables规则、端口号空间
  • IPC Namespace：隔离进程间通信（信号量、消息队列、共享内存）
  • UTS Namespace：隔离主机名和域名，容器可以有自己的hostname
  • User Namespace：隔离用户和用户组ID，容器内root用户在宿主机上只是普通用户

再加上cgroup做资源限制（CPU/内存/IO/网络带宽配额）、OverlayFS做联合文件系统、seccomp做系统调用过滤，就构成了完整的容器运行时。

Namespace就像给进程戴了一副VR眼镜：它还是运行在宿主机上的普通进程，但是戴上眼镜后它看到的是一个完全独立的世界——自己的PID=1、自己的文件系统、自己的网卡、自己的主机名，它以为自己独占整个计算机，实际上和其他容器共享同一个内核，比虚拟化（KVM）轻量得多，启动快、开销小。

KVM 硬件虚拟化：EPT二级地址翻译

arch/x86/kvm/ · 基于CPU硬件虚拟化扩展（VT-x/AMD-V）

KVM把Linux内核变成一个Hypervisor，每个虚拟机都是一个普通的QEMU进程，vCPU是进程里的线程，通过CPU硬件虚拟化扩展直接在CPU上执行虚拟机代码，不需要二进制翻译，性能接近物理机。

核心机制EPT（扩展页表）：硬件自动完成两层地址翻译——客户机虚拟地址（GVA）→ 客户机物理地址（GPA）→ 宿主机物理地址（HPA），不需要软件影子页表，内存虚拟化性能极高。

术语表

task_struct

套接字缓冲区，网络包在协议栈中流转的唯一载体，通过四个指针移动实现加头/去头零拷贝，定义在include/linux/skbuff.h
EEVDF
最早虚拟截止时间优先调度器，6.6版本正式替代使用了16年的CFS，调度更公平、交互响应延迟更低
VFS
虚拟文件系统，抽象层，实现一切皆文件，通过file_operations函数指针表统一所有文件类对象的操作接口
RCU
读-拷贝-更新同步机制，读侧完全无锁无等待，极高读性能，适合读多写少场景，内核并发性能的核心优化
NAPI
网络包接收机制，中断+轮询混合模式，高流量下避免中断风暴，批量处理网络包提升吞吐量
Netfilter
网络包过滤框架，五个钩子点贯穿整个包路径，iptables/nftables/eBPF防火墙都基于此实现
Namespace
内核资源隔离机制，六大Namespace实现容器的视图隔离，让进程看起来独占整个系统
EPT
扩展页表，Intel VT-x硬件虚拟化提供的二级地址翻译机制，硬件自动完成GVA→GPA→HPA翻译，无需软件影子页表
伙伴系统
物理页分配器，以2的幂次为单位分配连续物理页，通过伙伴合并机制解决外部碎片问题
