本体层级体系

总纲 · 内核即本体

一切皆抽象

从VFS的四大对象到调度器类，从socket抽象到设备模型，Linux本体的核心是用统一抽象屏蔽异构实现。所有实体都通过函数指针表实现多态，与面向对象本体的继承多态本质同构。

机制策略分离

机制定义本体的不变约束（如进程调度的实体是task_struct），策略定义可变的行为（如CFS/RT/DL的调度算法）。这是内核可演化性的本体论根基，也是所有子系统设计的第一原则。

分层环绕闭合

从硬件抽象层到系统调用接口，内核本体呈现清晰的分层结构，层与层之间通过严格定义的接口交互。同时所有路径最终闭合（如sk_buff从分配到释放，进程从fork到exit），无本体泄漏。

内核三法印

诸法无我 · 一切皆文件

VFS以统一的file_operations接口假名安立一切资源，无论是块设备、管道、socket还是/proc下的内核对象，都被抽象为文件描述符。万法平等，无有高下，使用者无需感知底层差异。

一即一切 · 宏内核圆融

单地址空间下所有子系统直接协作，函数调用零开销互摄互入。进程调度可以直接触发内存回收，网络收包可以直接唤醒等待进程，体用不二，没有微内核的IPC边界割裂。

缘起性空 · 引用计数

kref引用计数是内核对象生命周期的本体法则：对象本无自性，因缘聚合（引用计数>0）则存在，因缘消散（引用计数=0）则销毁。没有永恒的对象，只有流转的引用。

内核核心本体

主轴：分类驱动 + 状态驱动

进程管理的本体骨架是调度器类的分类继承体系加进程生命周期状态机的双轴结构。task_struct作为核心实体，承载所有调度器类抽象接口，不同调度策略通过sched_class多态实现。

核心实体
task_struct · sched_class · sched_entity · rq · cfs_rq
核心关系
继承：sched_class → stop/dl/rt/cfs/idle_sched_class；包含：rq包含cfs_rq/rt_rq
核心公理
vruntime单调递增 · 高优先级调度器类始终抢占低优先级类 · 时间片完重新入队

CFS 完全公平调度器本体

CFS的本体核心是vruntime虚拟运行时间，通过红黑树实现O(log n)选择最小vruntime进程。它不分配固定时间片，而是根据系统负载动态计算进程应该获得的CPU时间比例，实现"众生平等"的因果调度。

  • • nice值对应进程权重，决定CPU时间分配比例，不是固定优先级
  • • 调度延迟target_latency是所有进程至少运行一次的周期，默认20ms
  • • 最小粒度min_granularity防止进程切换过频，默认1ms
  • • 组调度通过task_group实现层级CPU配额，对应cgroup本体

进程生命周期状态机

调度器类优先级层级

主轴：映射驱动 + 分类驱动

内存管理的本体核心是虚拟地址到物理地址的四级映射，叠加页分配器、slab分配器的分类分配体系。所有内存操作最终都通过页表完成转换，缺页异常是地址映射动态建立的触发机制。

核心实体
struct page · mm_struct · vm_area_struct · pgd/pud/pmd/pte
核心映射
虚拟地址 → 页表 → 物理页 · 文件偏移 → 页缓存 → 用户地址空间
写时复制
fork时共享只读页，写入时触发缺页异常复制物理页，是缘起性空的极致体现

三级内存分配器体系

页分配器（伙伴系统）
以2^n阶为单位分配连续物理页，解决外部碎片，核心是free_area数组
slab/slub分配器
对伙伴系统的页再切分，按对象大小建立专用缓存，解决内部碎片，用于内核小对象分配
vmalloc
分配虚拟地址连续但物理地址不连续的内存，用于大内存需求且不需要物理连续的场景

四级页表映射结构

内存回收与水位线

每个内存节点有min/low/high三个水位线，页分配时低于low触发直接回收，低于min触发OOM杀死进程。LRU链表分为active/inactive匿名/文件四类，页面老化算法模拟时间流逝，不常用的页面被换出或丢弃。

主轴：过程驱动

中断是硬件事件到内核处理路径的触发机制，本体核心是中断上下文与进程上下文的严格边界，以及硬中断→软中断→线程中断的三级处理流水线，保证高优先级事件快速响应，低优先级处理延后执行。

三级中断处理
硬中断（不可抢占，临界区短）→ 软中断（可抢占，不可睡眠）→ 工作队列（进程上下文，可睡眠）
NAPI机制
中断到轮询的自适应切换，高负载时关闭中断用轮询处理，避免中断风暴，是定慧等持的体现
中断亲和性
将中断绑定到指定CPU，结合SMP架构实现并行处理，提高缓存局部性

中断处理流水线

同步原语本体层级

内核同步原语形成一个清晰的能力层级，从轻量级到重量级按适用场景排列，核心原则是在满足并发安全的前提下用最轻的原语。

原子变量
单指令原子操作，无等待，用于计数器，最轻量级
自旋锁 spinlock
忙等待，临界区短，不可睡眠，中断上下文可用
信号量 semaphore
睡眠等待，临界区长，允许持有锁时睡眠
互斥锁 mutex
比信号量轻量，只有持有者能解锁，优先于信号量使用
RCU 读拷贝更新
读端完全无锁，写端拷贝更新后等待宽限期结束释放旧对象，读多写少场景性能最优

锁的适用场景决策树

TCP/IP 协议栈本体

重点示范子模块 主轴：状态驱动 + 过程驱动

以 sk_buff 生命周期为本体主线

TCP/IP协议栈是所有子模块中本体最完整、自洽性最高的模块。整个协议栈围绕sk_buff网络报文结构体的生命周期展开：发送路径从上到下层层加封装，接收路径从下到上层层解封装，TCP状态机驱动连接生命周期，Netfilter钩子点实现流量干预，conntrack跟踪连接状态。

TCP 状态机与十二缘起

TCP连接从建立到关闭的完整状态流转与佛教十二因缘流转还灭完美对应：三次握手是三事和合入胎，数据传输是住胎受报，四次挥手是寿暖识尽舍报，TIME_WAIT是中阴身等待旧业消尽。

数据收发四层流转

发送路径（顺缘起 · 层层封装）
4

3

TCP可靠传输因果律

序号与ACK：业种不失
每个字节都有序号，ACK确认所有已收到字节，丢包必然重传，因果不爽
滑动窗口：观机逗教
接收窗口根据消费能力动态调整，发送方按接收方能力发送，不溢不欠
拥塞控制：消旧业不造新殃
慢启动探测带宽，拥塞避免线性增，丢包时乘性减，主动适应网络容量
三次握手：三事和合生
SYN→SYN+ACK→ACK，客户端、服务端、网络三者和合，连接方才成立
四次挥手：寿暖识尽
FIN→ACK→FIN→ACK，双向分别关闭，确保所有数据传输完毕才销毁连接

文件系统本体

主轴：映射驱动 + 分类驱动

文件系统的本体核心是VFS虚拟文件系统层的四大对象抽象，为上百种不同文件系统提供统一接口。它定义了"一切皆文件"的本体契约，所有具体文件系统只要实现这套接口就能被内核无缝接入。

VFS 四大核心对象
super_block（超级块，文件系统实例）· inode（索引节点，文件本体）· dentry（目录项，路径解析缓存）· file（打开的文件实例）
核心映射关系
文件路径 → dentry → inode → 页缓存 → 磁盘块；不同文件系统通过file_operations多态实现
挂载机制
mount命名空间实现文件系统的组合叠加，根文件系统为本体根，其他文件系统挂载到目录树节点上

文件系统分类谱系

页缓存与IO栈

页缓存是文件IO性能的核心，文件数据被访问时先缓存到内存，写操作默认先写缓存再异步回写（write-back），direct IO绕过缓存直接访问磁盘。IO调度器对请求进行排序合并，减少磁盘寻道时间。

noop：无调度，直接下发，适合SSD
deadline：读写请求设超时期限，防止饿死
cfq/bfq：按进程分配IO带宽，公平调度
mq-deadline：多队列版本，适配现代高速SSD

特殊文件系统本体

procfs
内核状态暴露，进程信息、系统参数虚拟文件
sysfs
设备模型与驱动信息的层次化展示
tmpfs
内存文件系统，临时文件存储，速度快
devtmpfs
设备节点自动创建，/dev目录的自动管理

驱动与虚拟化本体

设备模型：匹配驱动主轴

设备模型的本体核心是bus-device-driver三元匹配结构：总线负责注册设备和驱动，当设备和驱动匹配成功时调用驱动的probe函数完成初始化。这套解耦设计让硬件热插拔、驱动独立开发成为可能。

中断处理下半部机制

硬中断只做最紧急的硬件操作（如读寄存器、ack中断），剩下的耗时处理延后到下半部执行：软中断是静态定义的可延迟执行上下文，tasklet基于软中断实现单CPU串行执行，工作队列把工作交给内核线程在进程上下文执行。

虚拟化：边界驱动主轴

虚拟化的本体核心是资源边界的重映射与隔离：通过硬件辅助虚拟化（Intel VT-x/AMD-V）把物理CPU/内存/IO抽象成虚拟资源，每个虚拟机看到的是一套完整但虚拟的硬件。容器则更轻量，通过namespace隔离视图，cgroup限制资源用量。

容器六大namespace
mnt（挂载点）· pid（进程树）· net（网络栈）· ipc（进程间通信）· uts（主机名）· user（用户ID）
cgroup资源控制
cpu · memory · blkio · devices · cpuset 等子系统，实现资源的配额与优先级控制
KVM本体
内核模块把Linux变成hypervisor，/dev/kvm接口提供虚拟机创建能力，用户态QEMU模拟设备

Linux 本体演化时间轴

1991

0.01 版本发布

Linus Torvalds发布第一个Linux版本，仅支持i386架构，有简单的进程调度和内存管理，没有网络栈，本体骨架初步形成。

1994

1.0 正式版

支持TCP/IP协议栈，VFS虚拟文件系统层成型，本体核心三大件（进程、内存、文件系统）基本稳定，开始支持多架构。

1996

2.0 版本

支持SMP多处理器，新增内核线程机制，网络栈支持Netfilter钩子框架，本体开始支持多核心并发扩展。

2003

2.6 版本

CFS完全公平调度器前身引入，O(1)调度器成为默认，支持NUMA架构，新增sysfs/debugfs，驱动模型成熟，Linux开始进入企业级服务器市场。

2007

CFS 调度器合入

2.6.23版本正式合入CFS调度器，取代O(1)调度器，vruntime虚拟运行时间机制成为进程调度本体的核心，真正实现完全公平。

2008

cgroups 合入主线

控制组机制合入内核，为容器技术奠定资源控制本体基础，后续namespace逐步完善，最终催生Docker/Kubernetes云原生生态。

2011

3.0 版本

KVM虚拟化成熟，支持透明巨页、Btrfs文件系统，多队列块层引入，IO栈本体开始适配高速SSD硬件。

2015

4.0 版本

eBPF机制引入，允许用户态安全加载在内核中执行的字节码，开启内核可扩展编程新时代，TCP栈支持BBR拥塞控制。

2020

5.0+ 版本

io_uring异步IO框架合入，大幅提升IO性能，支持Rust内核驱动开发，持续优化云原生场景性能，本体仍在持续演化中。

本体演化规律

核心本体不变性

进程/内存/文件系统三大核心本体从1.0到6.x保持架构稳定，核心抽象没有颠覆性变化，体现了本体设计的正确性。

外延持续扩展

新机制都是在核心本体之上的增量扩展：cgroup基于进程调度、io_uring基于VFS、eBPF基于内核执行上下文，没有推翻核心。
